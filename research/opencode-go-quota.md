# OpenCode Go authentication and quota for CLIProxyAPI

Checked 2026-09-24 against OpenCode's official documentation and source, CLIProxyAPI's plugin host source, and the OpenCode Go plugin's own release source. Live verification used Rome's configured credential without printing or storing its value.

## Findings

1. **Use the OpenCode Go API key.** OpenCode's [Go setup guide](https://opencode.ai/docs/go) and [provider guide](https://opencode.ai/docs/providers) tell users to sign in to the Console, copy an API key, and paste it into the Go provider. The Go usage route's [implementation](https://github.com/anomalyco/opencode/blob/dev/packages/console/app/src/routes/zen/go/v1/usage.ts) authenticates `Authorization: Bearer <key>` by looking up an active key in `KeyTable`; it does not accept a browser session or implement an OAuth exchange. This does not prove OAuth can never be added, but there is no documented OpenCode Go OAuth login for inference or quota, and adding one now would depend on an unsupported flow.

2. **An official quota endpoint exists:** `GET https://opencode.ai/zen/go/v1/usage` with the Go API key as a Bearer token. OpenCode [merged the endpoint](https://github.com/anomalyco/opencode/pull/16513) on 2026-08-11. Its [route source](https://github.com/anomalyco/opencode/blob/dev/packages/console/app/src/routes/zen/go/v1/usage.ts) returns `usage.rolling`, `usage.weekly`, and `usage.monthly`; each has `status` (`ok` or `rate-limited`), `percent` (usage consumed, 0–100), and `resetsAt` (ISO timestamp). Missing or invalid key returns 401, and an authenticated user without a Go subscription returns 403. Compute a remaining percentage as `100 - percent`; the route does not return remaining dollars or a per-model breakdown.

3. **The windows are determined by OpenCode.** Its [Go guide](https://opencode.ai/docs/go) describes five-hour, weekly, and monthly limits, with each model's limits expressed as dollar amounts. The [usage route](https://github.com/anomalyco/opencode/blob/dev/packages/console/app/src/routes/zen/go/v1/usage.ts) reads one Go subscription usage row for the key's user and computes three summary windows using [Subscription analysis functions](https://github.com/anomalyco/opencode/blob/dev/packages/console/core/src/subscription.ts). Thus the endpoint is suitable for account-level quota cards but cannot directly show the remaining quota of a particular model. Any exact model-specific remaining budget would need another supported source.

4. **The existing inference plugin already supports a quota page.** The plugin's [v0.1.9 README](https://github.com/massiveits/opencode-go-cliproxyapi/blob/v0.1.9/README.md) says Management Center includes a separate **OpenCode Go Quota** page. It lists configured credentials without making upstream calls on page load, refreshes each credential manually, and keeps quota values separate from routing and CLIProxyAPI's native quota page. The [v0.1.9 release notes](https://github.com/massiveits/opencode-go-cliproxyapi/blob/v0.1.9/RELEASE_NOTES.md) add a Refresh All button. This makes updating or extending that plugin a smaller path than creating another inference plugin. Verify the deployed plugin version and whether its page is visible before implementing a replacement.

5. **The Auth Files card does not show plugin quotas.** The Management Center's [Auth Files provider list](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/main/src/features/authFiles/constants.ts) hardcodes the quota-capable providers, and [card logic](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/main/src/features/authFiles/logic.ts) hides the quota section for every other provider. `opencode-go` is absent. CLIProxyAPI's [auth-file quota serializer](https://github.com/router-for-me/CLIProxyAPI/blob/v7.2.146/internal/api/handlers/management/auth_files.go) also clears passive quota observations for unsupported providers; its [allowlist](https://github.com/router-for-me/CLIProxyAPI/blob/v7.2.146/sdk/cliproxy/auth/quota_signals.go) includes only `claude` and `codex`. A plugin cannot add a refresh control to the existing Auth Files card by itself.

6. **The smallest native-card integration is a Management Center change.** Add `opencode-go` to its quota provider types and an adapter in the [quota adapter registry](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/main/src/features/quota/providers/index.ts). That adapter can call the existing authenticated `POST /v0/management/plugins/opencode-go-cliproxyapi/quota-usage` route and render its three windows. This avoids changing the inference plugin or CLIProxyAPI's core quota observation model. It does require building and serving a modified Management Center, or getting the change accepted upstream. The plugin's existing page remains a separate view and its browser-resource route is Authelia-protected in Rome's Caddy configuration.

## Practical next step

Rome runs plugin **v0.1.9** with an **OpenCode Go Quota** menu entry. Its authenticated `POST /v0/management/plugins/opencode-go-cliproxyapi/quota-usage` returned HTTP 200 with rolling, weekly, and monthly statuses and percentages using the configured credential. No secret or raw response was recorded here.

The existing plugin covers the three-window quota display on its own page at `/v0/resource/plugins/opencode-go-cliproxyapi/quota`. It does **not** put quota in the Auth Files card shown in the user's screenshot. To add that card, change the Management Center as described above; writing another inference plugin would not change the card's hardcoded provider list. Keep the Go key in the existing CLIProxyAPI credential configuration and omit it from logs, URLs, and Git. OpenCode's [client guidance](https://opencode.ai/docs/go) also asks coding agents to send a stable session ID and identify their user agent for inference requests.
