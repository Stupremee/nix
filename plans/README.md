## Dependency notes

- No plan hard-depends on another, but **004 should land first in practice**.
  It is the only plan that creates a way to verify the others: today
  `nix flake check` runs one check (treefmt), the darwin and home-manager
  configurations are never evaluated, and the Python test suite is disabled.
  Plans 001–003 all change behavior on a host that runs an identity provider
  and controls a heat pump.

  block, while 001 touches only the `age.secrets` block. Sequence them if the
  same executor runs both, to avoid a conflict.

## Findings considered, not planned

Real but lower leverage, or needing a decision this audit cannot make:

- **SSH algorithm downgrade on rome** (`configurations/nixos/rome/default.nix:67-69`):
  `HostKeyAlgorithms` is set without a `+` prefix, so it *replaces* rather than
  extends — rome offers only SHA-1 `ssh-rsa` host keys, retiring the ed25519 key
  that impermanence provisions and backs up. Added for one Brother scanner.
  Fix is to scope it to a `Match User paperless` block. Not planned because
  getting it wrong risks locking out SSH to the server, including the deploy
  path — this wants a human at a console, not an executor.
- **Scanner has an interactive shell** (`configurations/nixos/rome/default.nix:61-66`):
  the `paperless` service account gets `useDefaultShell = true` plus an
  unrestricted authorized key held by a consumer scanner. Should be
  `restrict,command="internal-sftp"`. Same reason as above — verify against the
  device.
- **Vendored Caddy is stale and carries an unused plugin**
  (`packages/caddy/`): pinned at 2.9.1 (Jan 2025), replaces `pkgs.caddy`
  globally via the overlay, and compiles in `greenpau/caddy-security` — which
  no Caddyfile in this repo uses (auth is done by Authelia `forward_auth`).
  That plugin drags in SAML, LDAP, step-ca, and badger. The whole vendored tree
  is likely replaceable by `pkgs.caddy.withPlugins` with just the cloudflare DNS
  plugin, which would let nixpkgs own the base version. Worth doing; deferred
  because it needs a `vendorHash` recompute and a live check that nothing
  outside the repo uses caddy-security.
- **SunSpec correctness bugs** (deferred out of plan 004 deliberately): a NaN
  sensor state clamps to the register *maximum* rather than being rejected
  (`ha_client.py:31` + `:114`); a Home Assistant outage serves the last-known
  values indefinitely with no staleness signal, and if the export simulator was
  active it stays latched (`main.py:43-44`, `grid_export_simulation.py:31`);
  several scale factors disagree with the values written, so current and DC
  voltage read 10× low (`register_store.py:101` vs `:190-193`); no HTTP timeout
  on the HA client (`ha_client.py:56-62`). Each changes what the heat pump sees
  and deserves its own plan with a rollback story — much easier to write once
  plan 004 makes the test suite run.
- **Six dead modules** orphaned by the `aerial`/`gleba` host removal:
  `modules/nixos/{amd-gpu,gaming,laptop,localsend,logitech}` and
  `modules/home/mako` are auto-imported into every host but enabled by none.
  Pure deletion, low value, trivially recoverable from git.
- **Broken desktop tooling on baldon**: `modules/home/rofi/powermenu.sh:27,37,50,60`
  background the confirmation dialog inside command substitution
  (`ans=$(rdialog &)`), so shutdown/reboot/suspend confirmation is unreliable;
  `:47` calls `swaylock`, which is not installed anywhere (the repo uses
  `hyprlock`). `modules/home/hyprland/default.nix:167-168` bind `makoctl` but
  `my.mako` is never enabled, so there is no notification daemon and
  `notify-send`/`slurp` in the screenshot script are absent too. Real, but
  desktop-only annoyance.
- **`with lib;` at file scope in 49 of ~60 modules**: the long-discouraged Nix
  pattern — defeats LSP go-to-definition, makes typos eval-time failures, and
  blocks `deadnix`. A mechanical `inherit (lib) ...` migration. Genuinely worth
  doing for maintainability but touches nearly every file; best done
  incrementally when touching a module, not as one unreviewable sweep.
- **Unused flake inputs**: `lanzaboote` (declared, pinned to a tag from
  2025-01-23, referenced nowhere — both hosts use plain systemd-boot) and
  `hyprpanel` (the config uses home-manager's built-in `programs.hyprpanel`
  module, not the input). Both drag redundant nixpkgs/home-manager trees into
  the lock. Also `impermanence` has no `follows`, pulling a second full nixpkgs.
- **`nixos-unified.primary-inputs` omits `agenix` and `agenix-rekey`**
  (`modules/flake/toplevel.nix:26-36`), so `nix run .#update` never bumps the
  two inputs that gate access to every secret. `agenix` is ~6 months stale.
- **Domain hardcoded across nine modules**: `stu-dev.me` appears in ~20 sites;
  only `my.stremio.domain` was parameterized. A `my.domain` option would make
  the service modules reusable.
- **treefmt covers only Nix and shell**: ~2000 lines of Python, the Go package,
  Lua ftplugins, and 12 JSON theme files have no formatter or linter, while the
  exclude list mentions formatters that were never enabled.

## Rejected — verified false or by-design

- **"`git-identity.sh` corrupts repo config when fzf is cancelled"** — reported
  by an auditor, disproved empirically. With an empty `ID`, the guard
  `git config --global --get-regexp "user..name"` does *not* match
  `user.work.name` (git's regex needs exactly two characters between `user` and
  `name`), so it exits 1 and the script bails correctly. The missing
  `set -euo pipefail` is a minor style issue, not a correctness bug.
- **"`allowed-users = [ "root" ]` locks `stu` out of the Nix daemon"** —
  `modules/nixos/nix-common/default.nix:84-85` and
  `modules/nixos/user/default.nix:83-86` both contribute to the same list
  option; NixOS merges them, so `stu` is present. Not a bug.
- **`secrets/restic-password` and `secrets/rclone.conf` lacking `.age`** — both
  verified age-encrypted (`age-encryption.org/v1`, piv-p256 recipient). A naming
  inconsistency worth fixing eventually, not an exposure.
- **Paperless OIDC `client_secret`** (`modules/nixos/paperless/default.nix:74`)
  — a `pbkdf2-sha512` digest, which is Authelia's documented way to store client
  secrets in config. The plaintext lives in the encrypted env file. By design.
- **`nvf` and `disko` following `nixpkgs-unstable` while the rest follow
  stable** — correct, not drift: the neovim config is built against
  `pkgsUnstable`, and disko is only used at install time.
- **The `RLock` in `register_store.py:40`** — technically unnecessary (single
  event loop, no `await` inside the lock), but harmless and removing it would
  create a latent hazard if threading is ever introduced.
